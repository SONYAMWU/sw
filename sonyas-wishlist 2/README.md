# SONYA’S WISHLIST

Персональный архив желаний: молочный фон, современный шрифт Manrope, рукописные акценты Caveat, рисованный красный бант и карточка-послание друзьям. Это исходный проект, который нужно один раз подключить к вашему Supabase и опубликовать. Поддельных подарков и локальных бронирований нет. Три изображения-референса в сообщении не приложены: оформление основано на текстовом описании.

## Обновлённое оформление

Звёздочка заменена рисованным бантом. Заголовки и текст используют Manrope, заметки — Caveat. Добавлены бумажная карточка со скрепкой, монограмма, пастельные категории и новое оформление карточек подарков. Функции Supabase и бронирований остались прежними. Повторно запускать SQL из-за смены дизайна не нужно.

Если у вас уже есть настроенная копия сайта, для обновления оформления замените только `index.html`, `src/main.tsx` и `src/style.css`; сохраните свой `.env` и переменные GitHub Actions.

## Как всё устроено

```text
Друзья → GitHub Pages → React + HashRouter
                        ├─ Supabase: опубликованные подарки (RLS, только чтение)
                        ├─ Realtime + обновление каждые 15 секунд
                        └─ Edge Function gift-actions
                            ├─ reserve → атомарная SQL-транзакция
                            ├─ cancel → проверка SHA-256 токена
                            └─ suggest → Turnstile + лимит → предложения
Соня → #/admin → Supabase Auth → проверка private.admins
                              ├─ управление подарками через RLS
                              └─ одобрение / отклонение через Edge Function
```

Фотографии хранятся в Supabase Storage или открываются по внешней ссылке. Только администратор может загружать напрямую в Storage; фотографии предложений проходят через сервер. Ссылки на изображения должны быть прямыми (на изображение, а не на страницу магазина). Внешние сервисы иногда запрещают показ своих фотографий: тогда скачайте фото и загрузите его файлом.

У каждого подарка одна строка в приватной таблице бронирований с уникальным `gift_id`. SQL обновляет подарок и создаёт бронь в одной транзакции. При двух одновременных запросах выигрывает один. Функции изменения статуса доступны только серверному `service_role`. Администратор приложения не имеет прав чтения таблицы токенов и изменения `reserved`. Владельцу самого проекта Supabase технически доступна база: приложение не может ограничить права владельца инфраструктуры. Имена, email и телефоны гостей не собираются. На сервере есть временный посоленный хеш IP для лимита; исходный IP не сохраняется в таблицах. Провайдеры хостинга могут вести свои технические журналы.

Токен создаётся браузером криптографически случайно, передаётся через HTTPS, сервер хранит SHA-256. Приватная ссылка существует только у получателя, не сохраняется в localStorage, не возвращается в API коллекции. Ссылка находится во фрагменте URL (`#`), который браузер не отправляет GitHub Pages. Не публикуйте её и не включайте запись тел запросов в серверных логах.

## 1. Что понадобится

- Бесплатные аккаунты GitHub, Supabase и Cloudflare (только Turnstile для защиты предложений).
- Node.js 22 LTS и редактор, например VS Code.
- Supabase CLI для публикации серверной функции. Установка: https://supabase.com/docs/guides/local-development/cli/getting-started

Бесплатные тарифы имеют квоты и могут менять условия; проект не требует платного хостинга frontend. Неактивный бесплатный Supabase может приостанавливаться — проверьте состояние проекта, если сайт не загружает коллекцию.

## 2. Создайте Supabase

1. Создайте новый проект на https://supabase.com/dashboard и сохраните пароль базы в менеджере паролей (сайту он не нужен).
2. Откройте **SQL Editor → New query**. Вставьте весь файл `supabase/migrations/001_wishlist.sql` и нажмите Run. Запускайте его один раз на новом проекте. Он создаёт таблицы, RLS, Storage и Realtime.
3. В **Project Settings → API** / **Connect** найдите URL проекта и публичный `anon` либо publishable key. Эти два значения разрешено публиковать: безопасность обеспечивается RLS.
4. Никогда не ставьте `service_role`, secret key, пароль базы или пароль администратора в `VITE_*`, GitHub Variables или исходный код. Server key уже доступен внутри Supabase Edge Functions.

## 3. Создайте администратора

1. В **Authentication → Users → Add user → Create new user** создайте пользователя с вашим email и сильным паролем, включите подтверждение email в форме создания (или подтвердите пользователя вручную).
2. Скопируйте UUID этого пользователя из Users.
3. Выполните в SQL Editor, заменив значение:

```sql
insert into private.admins(user_id) values ('UUID-ВАШЕГО-ПОЛЬЗОВАТЕЛЯ');
```

4. В настройках Auth отключите публичную регистрацию новых пользователей, если она вам не нужна. В приложении регистрации нет. Для смены/сброса пароля используйте панель Supabase Auth. Никому не передавайте административный аккаунт.
5. При необходимости сменить администратора удалите его UUID из `private.admins` и добавьте нового. Приложение проверяет актуальный список на сервере, а не email в коде.

## 4. Защита от спама

1. В Cloudflare откройте **Turnstile → Add widget**, тип Managed.
2. Добавьте hostname вашего GitHub Pages: например `sonya.github.io` (без пути репозитория). Для локальной проверки добавьте `localhost` и `127.0.0.1`.
3. Сохраните публичный Site key и приватный Secret key отдельно.
4. Публичный ключ пойдёт в `VITE_TURNSTILE_SITE_KEY`. Приватный — только в секреты Supabase.

Проверка Turnstile обязательна для предложения; если она недоступна, форма не отправляет подарок. Дополнительно сервер ограничивает предложения до 5 в час на хеш IP и операции бронирования/отмены до 60 в час. Пользователи одной сети делят лимит. Есть скрытое поле-ловушка в форме, ограничения размера, серверная проверка сигнатур файлов и URL. Входящий поток ограничен 7,1 МБ. Сервер не скачивает внешние URL, поэтому такие ссылки не приводят к серверным запросам на произвольные адреса. Ограничение по IP — дополнительная мера; для крупных публичных кампаний добавьте rate limiting на шлюзе и мониторинг квот Storage.

## 5. Опубликуйте серверную функцию

В терминале из корня проекта:

```sh
npx supabase login
npx supabase link --project-ref ВАШ_PROJECT_REF
npx supabase functions deploy gift-actions --no-verify-jwt
```

Project ref — идентификатор из адреса панели Supabase / URL проекта. Команда использует настройки `supabase/config.toml`. `--no-verify-jwt` нужен для анонимных гостей; административные действия отдельно проверяют настоящий access token через Auth и список администраторов. Публичный ключ в браузере не является администраторским.

В панели **Edge Functions → Secrets** добавьте:

| Имя | Значение |
|---|---|
| `ALLOWED_ORIGINS` | `https://sonya.github.io,http://localhost:5173,http://127.0.0.1:5173` с вашим доменом, без путей и завершающих `/` |
| `TURNSTILE_SECRET_KEY` | приватный Secret key Turnstile |
| `RATE_LIMIT_SALT` | длинная случайная строка (например, 32 случайных байта из менеджера паролей) |

Стандартные `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY` доступны функции автоматически. Не вставляйте их в файлы проекта. Список разрешённых origins должен совпадать с доменами виджета Turnstile. CORS ограничивает браузеры, но сам по себе не является защитой от спама.

## 6. Локальный запуск

1. Откройте папку проекта в редакторе.
2. Скопируйте `.env.example` в `.env`.
3. Заполните все три `VITE_*` значения из предыдущих шагов. Это публичные настройки.
4. Выполните:

```sh
npm install
npm run dev
```

Откройте адрес, который покажет терминал, обычно http://127.0.0.1:5173. После изменения `.env` перезапустите сервер.

```sh
npm test
npm run build
npm run preview
```

`npm test` проверяет SQL-миграцию и права в локальном PostgreSQL-движке PGlite (без аккаунта). `npm run build` проверяет TypeScript и создаёт `dist`. `npm run preview` показывает production-версию локально. Для бронирований в preview добавьте его origin (обычно http://localhost:4173) в `ALLOWED_ORIGINS` и hostname в Turnstile.

## 7. Загрузите на GitHub

1. Создайте пустой публичный репозиторий, например `sonyas-wishlist`.
2. Откройте терминал внутри папки, где лежит `package.json` (не в родительской папке архива).
3. Выполните, подставив свой логин:

```sh
git init
git add .
git commit -m "Create Sonya wishlist"
git branch -M main
git remote add origin https://github.com/ВАШ-ЛОГИН/sonyas-wishlist.git
git push -u origin main
```

GitHub может попросить авторизацию. `.env` исключён через `.gitignore`. Перед push убедитесь, что секретов нет в `git status` и добавленных файлах. `package-lock.json` прилагается: последующие установки могут использовать `npm ci`.

## 8. Включите GitHub Pages

1. В репозитории откройте **Settings → Secrets and variables → Actions → Variables**.
2. Создайте repository variables: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_TURNSTILE_SITE_KEY`.
3. В **Settings → Pages → Source** выберите **GitHub Actions**.
4. В **Actions → Publish wishlist → Run workflow** запустите публикацию. Следующие push в main будут публиковаться автоматически.
5. Дождитесь двух зелёных задач build и deploy. Ссылка появится в Settings → Pages: `https://ВАШ-ЛОГИН.github.io/sonyas-wishlist/`.
6. Проверьте, что этот origin есть в `ALLOWED_ORIGINS`, а hostname — в Turnstile.

Если сборка красная, откройте её журнал. Сайт не запускается двойным кликом по `index.html`: сначала нужна сборка. GitHub Pages хранит только frontend; SQL и функции публикуются в Supabase отдельно.

Маршруты используют `HashRouter`: панель `…/#/admin`, подарок `…/#/gift/UUID`, отмена `…/#/cancel?gift=…&token=…`. Они работают при обновлении и переходе по прямой ссылке без правил перенаправления. `base: './'` поддерживает путь репозитория. В адресе панели обязательно `/#/admin`, а не `/admin`.

## 9. Добавьте первые подарки

1. Откройте **for sonya ↗**, войдите вашим email и паролем.
2. Нажмите **Добавить подарок**. Введите название; остальные поля необязательны.
3. Загрузите JPG, PNG или WebP до 5 МБ либо вставьте прямую ссылку на изображение. При выборе обоих вариантов используется файл.
4. Цена указывается в рублях. Выберите категорию и приоритет. Сохраните.
5. Откройте коллекцию: новый подарок доступен всем. В панели можно изменить и удалить подарок. Удаление удаляет его бронь, поэтому сначала убедитесь, что хотите его убрать.
6. Предложения гостей появятся ниже в панели. **Одобрить** атомарно добавляет подарок в коллекцию; **Отклонить** скрывает его из списка ожидающих. Одно предложение невозможно одобрить дважды. При необходимости после одобрения измените категорию, приоритет и цену.

В административной панели нет имён бронирующих, секретных ссылок или кнопки снятия чужой брони. Если гость потерял ссылку, восстановить её невозможно. Не удаляйте и не создавайте подарок заново ради обхода чужой брони.

## 10. Проверка с двух устройств

Используйте тестовый подарок и два разных браузера/устройства, не административную сессию.

- [ ] Подарок виден на обоих устройствах.
- [ ] Нажмите забронировать на обоих почти одновременно и подтвердите: только один запрос успешен; другой сообщает, что подарок занят.
- [ ] На успешном устройстве скопируйте приватную ссылку в безопасное место. Интерфейс не закроет её сам.
- [ ] На обоих устройствах появляется reserved (Realtime; резервное обновление — до 15 секунд, также при возврате во вкладку).
- [ ] Обновите обе страницы: статус сохранился.
- [ ] Откройте панель: виден только статус, без личности и ссылки.
- [ ] Откройте приватную ссылку: до явного подтверждения бронь остаётся. Подтвердите: на обоих устройствах подарок доступен.
- [ ] Повторно используйте ссылку: отмена отклоняется. Забронируйте заново: старая ссылка не снимает новую бронь.
- [ ] Измените один символ токена: отмена отклоняется.
- [ ] В анонимном окне невозможно читать suggestions, private.reservations или менять gifts; SQL RPC reserve_gift/cancel_gift напрямую недоступны.
- [ ] У неадминистративного Auth-аккаунта также нет доступа к изменениям и модерации.
- [ ] Отправьте предложение, пройдя Turnstile: оно отсутствует в публичной коллекции до одобрения.
- [ ] Отправка без CAPTCHA, с неверной ссылкой, неподдерживаемым файлом или фото более 5 МБ отклоняется.
- [ ] Проверьте 6 предложений в течение часа: шестое ограничено (успешные/неуспешные попытки учитываются).
- [ ] На iPhone Safari проверьте формы, прокрутку модального окна, копирование ссылки и поворот экрана.
- [ ] Проверьте клавиатурой: Tab, Shift+Tab, Enter, Escape; модальные окна удерживают фокус средствами native dialog, фокус возвращается к исходному элементу.
- [ ] Откройте прямую ссылку подарка и обновите её на GitHub Pages.

Автоматическая интеграционная проверка доступна в `tests/integration.mjs`: создаёт и удаляет один тестовый подарок, проверяет гонку, отмену и RLS. Запускайте после настройки на тестовом проекте согласно комментарию в файле. Секретные пароли в тесты не записываются.

## Обслуживание и ограничения

Не загружайте в публичный bucket личные фотографии: URL фотографий предложений тоже публичны, хотя сами предложения доступны только администратору. Отклонённые предложения остаются в базе для истории; загруженные и заменённые фотографии автоматически не удаляются. Периодически удаляйте ненужные файлы через Storage, сверяясь со ссылками в gifts и suggestions, чтобы не исчерпать квоту. Сервер не сохраняет ссылки отмены. У проекта нет оплаты, корзины или отслеживания гостей.

Синхронизация работает через Realtime и резервный опрос; интерфейс может кратко показывать старый статус при потере сети, но сервер всегда отклонит повторную бронь. При отказе Clipboard API приватная ссылка остаётся в выделяемом поле. Для ссылки на подарок можно скопировать адресную строку. Интерфейс использует native dialog (Safari 15.4+), поддерживает reduced motion; рекомендуются актуальные браузеры. Шрифты загружаются из Google Fonts, есть системные fallback. Ни один локальный storage не используется для брони; Supabase Auth хранит только административную сессию стандартным способом.

Документация: [Vite / GitHub Pages](https://vite.dev/guide/static-deploy#github-pages), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Database functions](https://supabase.com/docs/guides/database/functions), [Edge Functions Auth](https://supabase.com/docs/guides/functions/auth-legacy-jwt), [Turnstile server verification](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).
